# 배분 규칙 보강 스킬

## 언제 쓰는지

- `web/engine.js`의 `classify(요구내용)` 결과가 시험 문항 정답과 맞지 않아 배분기준표 보강이 필요할 때 쓴다.
- `data/시험_요구문항_40건.csv`와 `data/요구자료_접수대장_2026국감_520건.csv`로 보강 전후 정확도를 비교해야 할 때 쓴다.
- 원본 `data/배분기준표_소관키워드_304건.csv`는 유지하고, 보강 사본 `rules_보강.csv`만 만들어야 할 때 쓴다.
- 이번 기준 상황은 `민원 서비스` 우선순위 1→3, `지방채` 1→2, `안전등급` 1→3 반영 뒤 시험 40건 1순위가 28/40에서 31/40으로 오른 상태다.

## 순서

1. `PROGRESS.md`, `CONTEXT.md`, 조직도 CSV, 배분기준표 CSV, 시험 문항 CSV를 먼저 읽는다. 필요하면 현재 엔진 시험도 `node test_engine.js`로 다시 실행한다.
2. 틀린 문항을 원인별로 묶는다. 예: 일반 키워드가 소관 키워드보다 앞서는 경우, 같은 키워드가 여러 과에 걸린 경우, 제외어가 부족한 경우, 우선순위가 낮은 경우.
3. 원인마다 고칠 방법을 1개씩 제안한다. 방법은 `제외어 추가`, `키워드 추가`, `우선순위 조정` 중에서 고르고, 새 규칙이나 변경 대상 과는 조직도 26개 과 안에서만 둔다.
4. 사용자가 고른 방법만 `rules_보강.csv`에 반영한다. 원본 배분기준표는 직접 고치지 않는다.
5. 고치기 전·후 정확도를 표로 비교하고 결과를 기록한다. 비교 항목은 시험 40건 1순위, 시험 40건 3순위 안, 접수대장 520건 1순위, 접수대장 520건 3순위 안, 새로 틀린 문항 수다. 끝나면 바꾼 규칙과 결과를 `PROGRESS.md`에 적는다.

## 끝나는 조건

- `rules_보강.csv`가 있고, 사용자가 고른 규칙만 원본과 달라야 한다.
- 바뀐 규칙을 `rule_id`, 키워드, 과, 변경 전 우선순위, 변경 후 우선순위로 확인해야 한다.
- 시험 40건과 접수대장 520건의 고치기 전·후 정확도 표가 있어야 한다.
- 새로 틀린 문항 수를 확인해야 한다.
- 조건이 `시험 40건 1순위 30건 이상`이고 `새로 틀린 문항 0건`이면, 이 절차를 스킬로 저장하거나 갱신한다.
- `PROGRESS.md`에 읽은 자료, 바꾼 파일, 바꾼 규칙, 정확도 결과, 남은 일을 적어야 한다.

## 하지 말 것

- 사용자가 고르지 않은 보강안을 반영하지 않는다.
- 원본 `data/배분기준표_소관키워드_304건.csv`를 직접 고치지 않는다.
- 조직도 26개 과 밖의 부서명을 만들거나 후보로 내지 않는다.
- 정확도를 올리기 위해 엔진 코드에 특정 시험번호나 문항 예외를 직접 쓰지 않는다.
- 새로 틀린 문항이 생겼는데 성공으로 보고하지 않는다.
- `.agents/skills/_스킬양식/SKILL.md` 또는 `agents/skills/_스킬양식/SKILL.md`가 없는데 있다고 말하지 않는다. 없으면 같은 4칸 구조로 새 스킬을 작성하고, 최종 보고에 양식 파일이 없었다고 적는다.
